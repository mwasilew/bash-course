Tips for the learner

The exercises use a practice folder called ~/playground, full of files made for the course: a treasure hunt, a messy folder to tidy, a story, a server log, lists and a scores table. The script below creates it and touches nothing else.

  1. Use a computer with Ubuntu (any recent desktop version).

  3. Open a new file in the nano editor:

    terminal

terminal

Meet the terminal

learner@ubuntu:~/playground$ echo · date · whoami · history

Goals

  • Know what the terminal and Bash are
  • Open a terminal and type your first commands
  • Use the keyboard shortcuts that save you time

Learn

What is the terminal?

Usually you tell the computer what to do by clicking with the mouse. The terminal is another way: you type instructions, called commands, and the computer types back its answer.

The program that reads your commands and runs them is called the shell. On Ubuntu the shell is called Bash. That is why this course is called "Bash for Beginners".

Why bother, when you have a mouse?

  • Many jobs are much faster to type than to click.
  • You can repeat a job a thousand times with one command.
  • Servers, robots, Raspberry Pis and supercomputers are mostly controlled this way.
  • Programmers use it every day.

Opening the terminal

Press Ctrl + Alt + T (all three keys at once).

Or: click Show Applications in the bottom-left corner, type terminal and press Enter.

A window opens with a line that looks something like this:

output
mieszko@laptop:~$

This is the prompt. It means "I am ready, type a command". It tells you:

Part Meaning
mieszko your user name
laptop the computer's name
~ the folder you are in (~ means your home folder)
$ the end of the prompt; you type after it

In this course, when you see a command like this:

terminal
echo hello

type it after the $ and press Enter. Do not type the $ itself.

Your first commands

echo repeats whatever you write after it:

terminal
echo hello
echo My name is Mieszko

date shows today's date and time:

terminal
date

whoami tells you your user name:

terminal
whoami

hostname tells you the computer's name:

terminal
hostname

uptime shows how long the computer has been switched on:

terminal
uptime

clear wipes the screen clean (your commands are not lost, the screen is just tidied):

terminal
clear

What a command looks like

Most commands have three parts:

output
command   -options   arguments
  ls        -l        Documents
  • the command: what to do
  • options (also called flags): how to do it; they usually start with -
  • arguments: what to do it to

Spaces matter! They separate the parts. echo hello works; echohello does not.

Try date with an option:

terminal
date +%A
date +%Y

The first prints the day of the week, the second prints the year.

When the computer does not understand

Type something that is not a command:

terminal
hello

You get:

output
hello: command not found

This is completely normal. The computer is just saying "I don't know a command called that". Check your spelling and try again.

Keyboard superpowers

Ctrl + C stop the running command / cancel what you are typing
Ctrl + L clear the screen (same as clear)

History

Bash remembers what you typed:

terminal
history

Each line has a number. To run command number 5 again, type !5. To run the very last command again, type !!.

Closing the terminal

Lesson 2 of 10

Finding your way around

learner@ubuntu:~/playground$ pwd · ls · cd

Goals

  • Understand how files and folders are organised in Linux
  • Know where you are, look around, and move to other folders
  • Understand paths, ~, . and ..
  • Find hidden files

Learn

Files and folders are a tree

Everything on the computer is stored in files. Files are kept in folders (in the terminal, folders are often called directories: same thing). Folders can contain other folders, so they form a tree, upside down:

output
/                       <- the "root": the very top
├── home
│   └── mieszko         <- your home folder (~)
│       ├── Desktop
│       ├── Documents
│       ├── Downloads
│       ├── Pictures
│       └── playground  <- our practice folder
├── usr
├── etc
└── tmp

Where am I? pwd

pwd means print working directory: it shows the folder you are in now.

terminal
pwd

You'll see something like /home/mieszko. That's your home folder.

What's here? ls

ls means list. It shows what is in the current folder:

terminal
ls

Ubuntu shows folders in blue and ordinary files in white.

Useful options:

terminal
ls -l        # long list: size, date, owner
ls -a        # all: show hidden files too
ls -la       # both together
ls -lh       # sizes in readable units like K and M

Anything after a # is a comment. Bash ignores it; it's there to explain things to you. You don't need to type the comments.

You can also list a folder without going into it:

terminal
ls Documents
ls /

Moving around: cd

cd means change directory.

terminal
cd playground
pwd
ls

Now you're inside playground. To go back up one level use .. (two dots mean "the folder above"):

terminal
cd ..
pwd

Some special shortcuts:

Command Takes you to
cd your home folder (from anywhere)
cd ~ also your home folder
cd .. one folder up
cd ../.. two folders up
cd - back to where you were before
cd / the root of the whole tree

Remember Tab! Type cd pla and press Tab: Bash completes playground/.

Paths

A path is the address of a file or folder.

An absolute path starts with / and gives the full address from the root. It works from anywhere:

terminal
cd /home/mieszko/playground/treasure

(Use your own user name instead of mieszko. whoami tells you what it is.)

A relative path does not start with /. It starts from where you are now:

terminal
cd ~/playground       # start from home
cd treasure/forest    # relative: from playground into treasure, then forest

~ is a shortcut for your home folder, so ~/playground is the same as /home/mieszko/playground.

One more: a single dot . means "this folder, right here". It will be useful later.

Hidden files

Files and folders whose names start with a dot (like .bashrc) are hidden. They're usually settings files. Normal ls doesn't show them; ls -a does:

terminal
cd
ls
ls -a

Names with spaces

Bash uses spaces to separate parts of a command, so names with spaces need quotes:

terminal
cd "My Folder"

Or avoid the problem: use _ or - instead of spaces in your own file names, like my_folder or my-folder.

A tree picture

The tree program draws folders as a tree. It may not be installed yet; you'll install it in Lesson 8. Until then, ls -R (recursive) lists everything inside, folder by folder:

terminal
ls -R ~/playground/treasure

  3. Go into playground and list it in the long format.
  4. Go to / and look around. Then go back with cd -.
  5. Go back home with one short command.

Making and changing files

learner@ubuntu:~/playground$ mkdir · cp · mv · rm

Goals

  • Create folders and empty files
  • Copy, move, rename and delete files and folders
  • Use wildcards to work with many files at once
  • Delete things safely

Learn

Do everything in this lesson inside the playground:

terminal
cd ~/playground

Making folders: mkdir

mkdir = make directory.

terminal
mkdir games
ls

Several at once:

terminal
mkdir music films books

A folder inside a folder that doesn't exist yet needs -p (parents):

terminal
mkdir -p school/maths/homework
ls -R school

Making empty files: touch

terminal
touch games/list.txt
ls games

touch creates an empty file (or, if the file already exists, just updates its date). Several at once:

terminal
touch books/a.txt books/b.txt books/c.txt

Copying: cp

cp = copy. First the thing to copy, then where to put it:

terminal
cp welcome.txt welcome_copy.txt     # copy and give it a new name
cp welcome.txt books/               # copy into a folder, keep the name
ls books

To copy a whole folder with everything inside, add -r (recursive):

terminal
cp -r shopping shopping_backup
ls shopping_backup

Moving and renaming: mv

mv = move. It moves a file to another folder:

terminal
mv welcome_copy.txt games/
ls games

In Linux, renaming is moving to a new name in the same folder:

terminal
mv games/welcome_copy.txt games/hello.txt
ls games

mv works on folders too, without needing -r:

terminal
mv films movies

Deleting: rm and rmdir

⚠️ Read this carefully. In the terminal there is no Recycle Bin. Deleted means gone forever.

Delete a file:

terminal
rm games/hello.txt

Delete an empty folder:

terminal
rmdir music

Delete a folder and everything inside it:

terminal
rm -r shopping_backup

Make rm ask before deleting each file (a very good habit when learning):

terminal
rm -i books/*.txt

Answer y for yes or n for no.

Safety rules:

  1. Always check where you are with pwd before deleting.
  2. Use ls with the same name first to see exactly what will be deleted.
  3. Never type rm -rf with / or ~ after it. It would try to delete everything.
  4. While learning, only delete things inside ~/playground.

Wildcards: working with many files at once

A wildcard is a special character that matches many names:

Wildcard Matches Example Matches
* anything (any number of characters) *.jpg cat.jpg, beach.jpg
? exactly one character song?.mp3 song1.mp3, song2.mp3
[...] one of the listed characters song[12].mp3 song1.mp3, song2.mp3

Look at the messy folder:

terminal
cd ~/playground/messy
ls
ls *.jpg
ls *.mp3
ls s*
ls song?.mp3

Always try a wildcard with ls first before using it with rm or mv. This way you see what it matches.

Brace expansion: a typing shortcut

Curly braces make Bash write out several words for you:

terminal
echo file{1,2,3}.txt
echo {a..e}
echo {1..10}

So this creates five folders in one go:

terminal
mkdir -p ~/playground/week/{monday,tuesday,wednesday,thursday,friday}
ls ~/playground/week

  1. In ~/playground, create a folder pets with an empty file dog.txt inside.
  2. Copy dog.txt to cat.txt in the same folder.
  3. Rename cat.txt to kitten.txt.
  4. Delete kitten.txt safely with rm -i.
  5. Delete the pets folder and everything left in it.

Pipes and redirection

learner@ubuntu:~/playground$ > · | · sort · uniq

Goals

  • Save the output of a command into a file
  • Feed the output of one command into another with a pipe |
  • Sort, remove duplicates, and cut columns
  • Build your own "command chains" to answer questions

This is where the terminal becomes really powerful. Each command does one small job well. Pipes let you snap them together like LEGO bricks.

Learn

terminal
cd ~/playground

Saving output to a file: >

Normally a command prints its output to the screen. > sends it into a file instead:

terminal
ls > list.txt
cat list.txt

⚠️ > replaces the whole file if it already exists:

terminal
echo "first" > test.txt
echo "second" > test.txt
cat test.txt              # only "second"

Adding to the end of a file: >>

>> appends: it adds to the end and keeps what was already there:

terminal
echo "first" > test.txt
echo "second" >> test.txt
echo "third" >> test.txt
cat test.txt

A handy diary trick:

terminal
date >> diary.txt
echo "Learned about pipes today" >> diary.txt

Errors are separate: 2>

Normal output and error messages travel on two different "channels". > only redirects normal output. To redirect errors use 2>:

terminal
ls story.txt nothere.txt > out.txt 2> errors.txt
cat out.txt
cat errors.txt

/dev/null is a special file that throws away everything sent to it, like a black hole:

terminal
ls nothere.txt 2>/dev/null

Pipes: |

The pipe | (Shift + \ on most keyboards) sends the output of the command on the left into the command on the right:

terminal
ls | wc -l

ls lists the files; instead of going to the screen, the list goes into wc -l, which counts the lines. So this counts the files in the folder!

More examples:

terminal
grep ERROR logs/server.log | wc -l          # how many errors?
cat story.txt | head -n 3                   # (same as head -n 3 story.txt)
ls -l /usr/bin | less                       # scroll through a long list
history | grep cd                           # which cd commands have I typed?

You can join as many commands as you like:

terminal
grep "logged in" logs/server.log | grep ala | wc -l

Sorting: sort

terminal
sort animals.txt              # A to Z
sort -r animals.txt           # Z to A (reverse)
sort numbers.txt              # careful! sorts as text: 100 comes before 15
sort -n numbers.txt           # sorts as numbers
sort -nr numbers.txt          # biggest first

Removing duplicates: uniq

uniq removes repeated lines, but only if they are next to each other. That's why you almost always sort first:

terminal
sort animals.txt | uniq
sort animals.txt | uniq -c          # count how many of each
sort animals.txt | uniq -c | sort -nr    # most common first
sort animals.txt | uniq -d          # only the ones that are duplicated

Cutting columns: cut

scores.csv is a table. Each line has columns separated by commas:

terminal
cat scores.csv

cut picks out columns. -d, says "columns are separated by commas", -f1 says "give me field (column) 1":

terminal
cut -d, -f1 scores.csv            # names
cut -d, -f2 scores.csv            # games
cut -d, -f1,3 scores.csv          # names and points

And sort the table by its third column, as numbers:

terminal
sort -t, -k3 -n scores.csv

(-t, = columns separated by commas, -k3 = sort by column 3.)

Skipping the header line

The first line of scores.csv is a header, not data. tail -n +2 means "start from line 2":

terminal
tail -n +2 scores.csv

Building a chain step by step

Question: Which game is the most popular?

Build the answer one brick at a time, running it after each step:

terminal
tail -n +2 scores.csv
tail -n +2 scores.csv | cut -d, -f2
tail -n +2 scores.csv | cut -d, -f2 | sort
tail -n +2 scores.csv | cut -d, -f2 | sort | uniq -c
tail -n +2 scores.csv | cut -d, -f2 | sort | uniq -c | sort -nr
tail -n +2 scores.csv | cut -d, -f2 | sort | uniq -c | sort -nr | head -n 1

This is how everybody builds long commands: add one piece, check, add the next.

See and save at the same time: tee

tee saves to a file and passes the text along to the screen:

terminal
sort animals.txt | uniq | tee unique_animals.txt

More small tools

terminal

output
-rw-rw-r-- 1 mieszko mieszko  168 Mar 14 10:00 welcome.txt
drwxrwxr-x 2 mieszko mieszko 4096 Mar 14 10:00 logs

The first column is the permissions. Let's take it apart:

output
 -    rw-    rw-    r--
type  user  group  others
  • type: - is a file, d is a directory (folder)
  • then three groups of three letters, for:
  • user: the owner of the file (you)
  • group: a group of users the file belongs to
  • others: everybody else

Each group of three is always in the same order:

Letter Permission For a file For a folder
r read look inside the file list what's in it
w write change the file add/remove files in it
x execute run it as a program go into it with cd
- — not allowed not allowed

So rw-rw-r-- means: the owner can read and write, the group can read and write, everybody else can only read. Nobody can run it as a program.

Changing permissions: chmod

chmod = change mode. Say who (u user, g group, o others, a all), add or remove (+ or -), and what (r, w, x):

terminal
echo "top secret" > secret.txt
ls -l secret.txt
chmod o-r secret.txt        # others can no longer read it
ls -l secret.txt
chmod u-w secret.txt        # even you can't change it now
echo "change" > secret.txt  # Permission denied!
chmod u+w secret.txt        # give it back

The most common use is making a script runnable, which you'll do in Lesson 9:

terminal
chmod +x myscript.sh

The boss of the computer: root and sudo

There is one special user called root who is allowed to do everything: change any file, install programs, even delete the whole system.

Your normal user can't change system files. Try:

terminal
ls -l /etc/hostname
echo test > /etc/hostname     # Permission denied. Good!

This protects the computer from mistakes. When you really need to do an admin job, you put sudo in front of the command. It means "do this as root". It asks for your password (nothing appears while you type it, not even stars; that's normal).

⚠️ The sudo rule: sudo turns off the safety net. Only use it when you know exactly what the command does, and never with a command copied from the internet that you don't understand. While learning, only use sudo with your teacher.

Variables

Decisions: if

terminal
#!/bin/bash
read -p "How old are you? " age

if [ "$age" -ge 18 ]; then
    echo "You are an adult."
else
    echo "You are not an adult yet."
fi

How it works:

  • if [ test ]; then ... fi. fi is if backwards and marks the end.
  • else is optional: what to do when the test is false.
  • Spaces inside [ ] are required! [ "$age" -ge 18 ] works, ["$age" -ge 18] does not.
  • Put variables inside the test in double quotes. It avoids errors when they are empty.
  • The lines inside are indented with spaces. Bash doesn't need this, but it makes scripts much easier to read.

More than two choices: elif

terminal
#!/bin/bash
read -p "What's the temperature? " temp

if [ "$temp" -ge 25 ]; then
    echo "It's hot! Shorts today."
elif [ "$temp" -ge 15 ]; then
    echo "Nice weather. A T-shirt is fine."
elif [ "$temp" -ge 5 ]; then
    echo "Take a jacket."
else
    echo "Brrr! Hat and gloves!"
fi

elif means "else if". Bash checks each test from the top and runs the first one that's true.

Repeating: the for loop

A for loop runs the same commands once for each item in a list:

terminal
for animal in cat dog fish; do
    echo "I like $animal"
done

The variable (animal) gets each value in turn. do ... done mark the commands to repeat.

Counting:

terminal
for i in {1..10}; do
    echo "$i x 7 = $(( i * 7 ))"
done

terminal

    echo "$file has $(wc -l < "$file") lines"
done

(wc -l < file prints only the number, without the file name.)

Every line in a file:

terminal

    echo "Hello, $animal!"
done

Repeating while something is true: while

terminal
#!/bin/bash
count=10
while [ "$count" -gt 0 ]; do
    echo "$count..."
    sleep 1
    count=$(( count - 1 ))
done

⚠️ If the test never becomes false, the loop runs forever. Press Ctrl + C to stop it.

Choosing from a menu: case

When one variable can have many values, case is neater than lots of elifs:

terminal
#!/bin/bash

case "$fruit" in

    banana) echo "Bananas are yellow." ;;
    cherry) echo "Cherries are small and red." ;;
    *)      echo "I don't know that fruit." ;;
esac

*) catches everything else. esac is case backwards.

Project A: My diary

A script diary.sh that keeps a diary in ~/diary.txt.

Must have:

  • When run with add, it asks "What happened today?" and appends the date and the answer to the diary.
  • When run with show, it shows the whole diary with less.
  • When run with last, it shows the last 5 entries.
  • When run with search WORD, it shows the entries containing that word.
  • When run with anything else (or nothing), it prints how to use it.

Ideas for extras: count how many entries there are; add a mood (happy, tired...) to each entry and show statistics of moods with sort | uniq -c.

Project B: The quiz master

A script quiz.sh that asks the player questions and keeps score.

Must have:

  • At least 5 questions (they can be about Bash!).
  • Says "Correct!" or "Wrong, the answer was ..." after each.
  • At the end prints the score, e.g. You got 4 out of 5.
  • Prints a different message depending on the score (e.g. 5 = "Bash master!", 3–4 = "Well done", less = "Try again").

Ideas for extras: read the questions and answers from a file questions.txt, one per line like What command shows your current folder?|pwd, and use cut -d'|' to split them; ask questions in random order with shuf; save the high score to a file.

Project C: The folder tidier

A script tidy.sh that takes a folder as an argument and sorts its files into subfolders by type.

Must have:

  • Checks that it was given exactly one argument, and that it is a folder.
  • Creates images, music, documents and other folders inside it, if they don't exist.
  • Moves .jpg, .png, .gif into images; .mp3, .wav into music; .txt, .pdf, .csv into documents; everything else into other.
  • Prints what it moved, and at the end, how many files went into each folder.

Ideas for extras: a --dry-run option that only shows what it would do without moving anything; work with upper-case endings like .JPG too.

Test it on ~/playground/messy (reset the playground first). Never test it on a real folder until you're sure it works!

Project D: System report

A script sysreport.sh that writes a report about the computer into report_DATE.txt.

Must have:

  • Date and time, user name, computer name, and how long it has been on.
  • Free disk space for /.
  • The 5 biggest items in your home folder (du -sh ~/* | sort -h | tail -n 5).
  • How many .txt, .jpg and .sh files are in your home folder.
  • Prints "Report saved to ..." at the end.

Ideas for extras: show the 5 processes using the most memory (ps aux --sort=-%mem | head -n 6); show a warning if the disk is more than 90% full.

#!/bin/bash
# Final project A: a diary kept in ~/diary.txt
# Usage: ./diary.sh add | show | last | search WORD

diary=~/diary.txt
touch "$diary"

case "$1" in
    add)
        read -p "What happened today? " entry
        echo "$(date '+%F %H:%M') | $entry" >> "$diary"
        echo "Saved!"
        ;;
    show)
        less "$diary"
        ;;
    last)
        tail -n 5 "$diary"
        ;;
    search)
        if [ -z "$2" ]; then
            echo "Usage: $0 search WORD"
            exit 1
        fi
        grep -i "$2" "$diary"
        ;;
    *)
        echo "Usage: $0 add | show | last | search WORD"
        exit 1
        ;;
esac
